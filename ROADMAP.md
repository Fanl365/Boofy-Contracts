# Boofy Contracts Roadmap

## Phase 1 — Migration baseline

- [x] Preserve upstream development history.
- [x] Establish Boofy project/team documentation.
- [x] Rebrand contract source tree while retaining legal attribution.
- [ ] Complete verification of imports, dependencies, scripts, and configuration.

## Phase 2 — Security and testing

- [ ] Run compiler and static-analysis checks.
- [ ] Execute vault, wrapper, oracle, and strategy test suites.
- [ ] Review ownership, fee, treasury, and multisig assumptions.
- [ ] Separate verified Boofy deployment configuration from historical upstream data.

## Phase 3 — Release readiness

- [ ] Document deployment and verification procedure.
- [ ] Define audit/review checklist for production contracts.
- [ ] Verify production deployment parameters independently.
- [ ] Publish first verified Boofy Contracts release candidate.

## Ongoing

Every production-facing contract change should have a corresponding issue or pull request with testing evidence. Historical upstream commits retain their original authorship and timestamps.
